# 房间事件节点

生产入口为 `prepare_full.py`，全量启动见 `README.md`。

- 先使用 SFT 同一转换函数把原始动作和 RGB 对齐为零起始的 pre-action 时序。
- 恢复原始场景/起点并拟合初始朝向，重放整条专家动作。所有帧通过 RGB 平均/最大误差门槛后，才使用模拟器房间区域候选。
- 取 agent 位置上方 0.5 m 所在 region AABB 的房间类别。多个 region 但类别一致可以使用；未知类别或不同类别重叠时记为不确定，不猜测。
- 同一明确类别连续出现两帧后确认。第一次确认只建立初始房间；此后确认的类别发生变化时，在第二帧产生 `newroom` 事件，不回溯到第一帧。
- 未知区域打断待确认计数，但保留上次确认类别。穿过未知区域进入新类别时记录 `crossed_unknown`。
- 同类别的不同房间 ID 不触发。不开启转向、固定距离、轨迹起终点等额外触发规则。
- 保存累计实际位移与归一化进度供追溯，它们不决定推理节点，也不被用作“指令已完成”的证据。

原有 `room_events.export()` 面向已人工批准的数据，仍要求 `alignment_status=approved`。全量准备脚本使用独立的 `numeric_pass` 状态并调用 `detect()`，明确区分自动数值门槛与人工批准。区域 AABB 近似、房间标签缺失和原始位姿缺失都会影响覆盖率；输出保留可追溯的数值和候选区域。
